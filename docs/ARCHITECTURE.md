# 아키텍처

## 처리 흐름

```text
파일 입력
  -> 확장자·크기·SHA-256 확인
  -> PDF 페이지 또는 이미지 추출
  -> 텍스트 품질 판정
      -> 텍스트 PDF: PyMuPDF 좌표/텍스트 사용
      -> 이미지 PDF/사진: 렌더링·전처리·PaddleOCR
  -> 쿠팡/네이버/일반 문서 분류
  -> 발급처별 파싱과 원본 증거(FieldEvidence) 기록
  -> 정규화·교차 검증·중복 후보 판정
  -> UI 검토·수정
  -> 4개 시트 Excel 출력 및 재열기 검증
```

## 핵심 설계

- `ReceiptRecord`가 문서 메타데이터, 페이지 추출 결과, 거래, 원본 매핑, 검증 이슈를 묶는 표준 단위입니다.
- 각 거래 필드는 `FieldEvidence`로 원본 라벨·원본 값·변환 값·파서·신뢰도를 추적합니다.
- 텍스트 기반 쿠팡 PDF는 원본 좌표와 문자를 우선 사용해 속도와 정확도를 확보합니다.
- 이미지 기반 네이버 영수증은 180 DPI 렌더링과 PaddleOCR 한국어 모델을 사용합니다.
- 파서는 분류 결과에 따라 선택되고, 알 수 없는 양식은 일반 파서가 최소한의 필드만 보수적으로 추출합니다.
- 페이지 추출·파싱 예외는 해당 페이지의 오류 레코드로 변환해 나머지 입력 처리를 계속합니다.
- UI 분석은 `QThread` 작업자로 실행해 긴 OCR 중에도 창이 응답하도록 구성했습니다.

## 검증 상태

- `정상`: 필수 관계와 신뢰도 기준을 통과
- `확인 필요`: 일부 값 누락, 낮은 신뢰도, 금액 불일치 또는 중복 후보
- `분석 실패`: 페이지 읽기, OCR 또는 파서 실행 실패

## Excel 출력

- `세무정리`: 거래일자·판매자·사업자번호·공급가액·부가세·면세·합계
- `상세내역`: 사용자가 선택 가능한 전체 거래·결제·상품·당사자 필드
- `오류내역`: 검증 이슈, 원본 인식값, 신뢰도, 수정 여부
- `원본매핑`: 표준 필드와 원본 라벨·값·변환 규칙의 추적 정보

저장 직후 openpyxl로 파일을 다시 열어 시트 구성과 기본 레이아웃을 확인합니다.
